# dsh-rc redesign plan

**A quiet control room**

2026-11-14. A design plan for dsh-rc, grounded in a survey of award-winning iOS apps, the six themes
in `public/style.css`, and the screens that actually exist in `public/index.html` and `public/app.js`.

**Scope:** UI only. No server, protocol, storage key, theme id, or dependency changes. The system
work exists to serve the board and the receipt, not to rebrand the app.

---

## The short version

dsh-rc does not need more features. It needs a hierarchy.

Right now the app shows four kinds of status at once (connection dot, Running now cards, session
row states, the telemetry bar), in 12 to 14 px type, inside six kinds of box. It reads as a very
good web dashboard. The redesign makes it read as an instrument: calm, legible, and obvious about
the one thing that matters at each moment.

The organizing idea is **attention before information**:

- The home screen answers *does anything need me?*
- A session answers *what is it doing, and what did it do?*
- Everything else (model, tokens, cost, plugins, prices) is one tap away, not on the glass.

Two structural moves carry most of the change:

1. **The board.** Sessions becomes Needs you → Running now → Unread → Today → Earlier, with each running
   session shown once, as a live row, instead of twice.
2. **The receipt.** A finished turn collapses to one row: *Passed · 2 files · 2 commands · 1m 12s*.
   Open it to review the work. A failed turn opens itself.

The visual identity comes from structure, not a new palette: SF Pro for language, SF Mono for
machine facts, a 4 pt spacing grid, five radii, two shadows (both for things that float), and
motion that explains state. All six themes stay, including the saved choice and its light/dark
behaviour; the redesign adds a semantic layer over the existing tokens instead of replacing them.

Build it in eight focused PRs, in three slices; three are larger because each replaces a screen.
Foundations first.

| Surface | Today | Becomes |
|---|---|---|
| Sessions | Centred title, two grey circles, Running now duplicating the list, filter sheet | Large title, search and Settings, Needs you → Running now → Unread → Today → Earlier, one bottom action |
| Running now | Separate cards above a second copy of the same sessions | Live rows inside the list, each with current step, clock, jobs and subagents |
| Session | Telemetry bar first, 14 px prose, a row per tool call, a large turn summary | Folder and context in the subtitle, 17 px prose, activity folded into a receipt |
| Composer | Input plus six controls, cryptic queue/steer chip | One field, plus, mic, send/stop; Queue/Steer only while running |
| Decisions | Stacked cards with equal-weight buttons | Focused cards, command readable, one filled primary, plan review in a sheet |
| Details | Three-line mono strip above every conversation | A grouped sheet one tap from the session menu |
| Settings | Two overlapping 13-row menus | One Settings, grouped rows, theme swatches, session menu separate |
| New session | Raw path input first | Recent folders, Browse, preset, Start pinned |

## 1. The bar: what "polished native" means here

"Native" is not iOS cosplay. A phone-first web app feels native when it respects the things iOS
users feel without naming:

- **Type is readable.** Body text at 17 px, not 12. Metadata at 13, not 10.5.
- **Touch is comfortable.** Every control at least 44 by 44 pt, with space between targets.
- **The platform is respected.** Safe areas, the keyboard, the back gesture, scroll edges, and
  sheets that can be dragged and dismissed.
- **One thing is primary.** One filled button per screen. One obvious next action.
- **Motion explains.** 120 to 320 ms, interruptible, and gone under Reduce Motion.
- **Nothing is decoration.** No shadows for depth on flat cards, no gradients behind buttons, no
  six kinds of border.

The research is useful, but it was gathered for a different kind of product: a warm consumer
journal with serif headings, picture tiles and three tabs. dsh-rc is a remote control for machine
work. The patterns transfer; the mood does not. Where the research
and this product disagree, this plan says so and gives the reason (section 7).

The six themes are both a constraint and an advantage. Because the palette is the user's, the
redesign cannot lean on teal, rust, or sage for identity. Its identity has to be type, spacing,
hierarchy, and motion, which are theme-independent. That is a better discipline than a new brand
colour, and it means the seasonal themes keep working without being repainted.

## 2. What dsh-rc is now

### 2.1 The surfaces

| Surface | What it is today | States it has to carry |
|---|---|---|
| **Sessions** (`#listView`) | Large-ish centred title, two grey circular bar buttons, Running now, a flat session list, a floating search button and New session pill | empty, search, filtered, offline, unread, waiting, failed, archived |
| **Running now** (`#running`) | A collapsible section of cards with elapsed, todo and context meters, jobs and subagents; the same sessions then appear again below | collapsed, expanded, 1 to many sessions, job output, stopping |
| **Session** (`#chatView`) | Compact header, a permanent telemetry bar, an optional goal bar, transcript, composer, decision cards | loading, streaming, working, approval, question, plan, failed turn, context full, disconnected |
| **Transcript** | 14 px prose, one row per tool call, diff cards, a turn summary card, a blinking working line | live, complete, partial history, failed, stopped, images |
| **Composer** | Input on its own row, then attach, templates (`Aa`), mic, queue/steer chip, send or stop | empty, typing, running, queued messages, attachments, dictation |
| **Decisions** (`#pending`) | Approval, question, plan cards pinned above the composer | waiting, folded, expired, multiple |
| **Sheets** (`#sheet`) | One shared bottom sheet holding the menu, filters, theme, new session, model, prices, commands, rename, export, archive, notifications, plugins, templates, schedules, QR | loading, error, forms, lists, destructive confirmation |
| **Toast** (`#toast`) | A dark rounded rectangle | success, error |

### 2.2 What is measured

These are counts from `public/style.css` today, not impressions:

- **45** declarations at 12 px, **18** at 14 px, **15** at 13 px, and exactly **one** at 17 px.
  The body of the app is 2 to 5 pt smaller than iOS body text.
- Font weights **550** and **650** appear 13 times. They are neither standard nor visible as
  distinct steps on most phones.
- **Nine** radius values (5, 6, 8, 10, 12, 14, 18, 20, plus 999) and one asymmetric bubble. **Seven**
  shadow variants, most on cards that do not need elevation.
- More than **25 distinct padding pairs**. There is no 4 pt grid.
- **Three** transitions in the whole app, all 150 ms. Sheets appear instantly. Press feedback is a
  background change on some rows and nothing on most buttons.
- **Three** permanent status surfaces in a session: the connection dot, the telemetry bar, and the
  working line. Add the goal bar and the turn summary and a phone shows five status treatments at
  once.
- The session list renders every running session **twice**: once in Running now, once in `#sessions`.

### 2.3 What is good and must survive

The redesign should not throw away the parts that already work:

- The **status glyph grammar**: spinner for working, amber for waiting, hollow ring for idle, plus
  shape redundancy in the colourblind and contrast themes. That is more thoughtful than most apps;
  the redesign makes the redundancy universal instead of theme-specific.
- **Approvals, questions and plan review above the composer.** Safety belongs in the conversation.
- **Running now's detail**: jobs, subagents, elapsed, and the two-tap stop. This is the app's
  signature and should get more prominent, not less.
- **The per-turn numbers** and the estimated cost. They are useful; they are just in the wrong
  place.
- **The demo screenshot harness**, which never touches a real instance. Keep it and extend it.
- **No build step.** Plain HTML, CSS and JS is a feature for a self-hosted tool. The redesign must
  not add React, Tailwind, an icon package, or a font download.
- **The copy that is already human**: "Needs approval", "Keep planning", "Reply instead", "Nothing
  is running". Keep the voice and cut the jargon around it.

## 3. The idea

### A quiet control room

The app is a room full of machines. A good control room does not show every gauge at equal size. It
shows the one light that is on, the one number that is moving, and a quiet board behind it.

Three rules follow:

1. **Attention before information.** Needs you first, live second, finished work third. Telemetry on
   demand. If nothing needs you, the screen should look calm.
2. **Two registers.** SF Pro for anything a person reads or says. SF Mono for anything a machine
   produced: commands, paths, model ids, token counts, elapsed time, code. Never mono for a label
   or a paragraph. This single rule does more for the app's character than a new palette.
3. **Colour and motion mean state.** Accent for the one primary action and the current selection.
   Green, amber and red only for outcomes, always with a glyph or a word. Motion only to explain a
   change of place or state.

### The loop the design serves

Open the app. See whether anything needs you. Open that session. Watch the current step or answer
the question. When the turn ends, read one receipt. Close it.

Everything that does not serve that loop is secondary. That is the whole plan.

## 4. What each screen becomes

### 4.1 Sessions: the board

**Current:** a centred 15 px "Sessions" with a connection dot, two 44 px grey circles, a Running now
section that duplicates the list, 14/12 px rows, a filter sheet, and two floating controls at the
bottom over a gradient.

**Becomes:** one sectioned list, in the order attention deserves. No filter control, because the
sections are the filter.

- **Large title, left aligned**, 34/41, semibold, 16 px gutter. It shrinks to a 17 px centred nav
  title on scroll, with a hairline that fades in at the scroll edge. This is the one piece of iOS
  chrome worth copying because it gives the screen a clear top and a calm empty state.
- **Two bar actions, no circles**: search (magnifier) and settings (gear). 44 by 44, bare 24 px
  glyphs. The connection dot goes; connection failure becomes a banner (section 4.9).
- **Section 1, Needs you**, only when something does. Amber 13 px header with a count, then one 56 px
  row per waiting session: status glyph, title, and a one-line 13 px mono summary of what is being
  asked (`Allow Bash: npm run build && npm test`, or the first line of the question). Tapping opens
  the session and lands on the decision card; **approval never happens from the list**. A session
  that is waiting belongs here and nowhere else.
- **Section 2, Running now**, the app's signature. A 13 px header with a count, then a **live row**
  per active session (anatomy in 4.2). A running session belongs here and nowhere else. Running
  rows are not cards: they are taller rows in the same list, so the screen has one container
  language.
- **Section 3, Unread**, for finished sessions you have not read yet: the same 56 px row, with the
  filled accent dot as its status glyph, and the normal metadata. If it failed, "Failed" is shown in
  red here too. A session that is waiting or
  running is not unread here; it is already in a higher section.
- **Section 4, Today**, and **Section 5, Earlier** (Yesterday, Previous 7 days, Older as quiet
  sub-headers). 56 px minimum, 17/22 title, 13/18 metadata: folder and relative time. A 16 px
  status glyph leads, a 12 px chevron trails. "Failed" is written in red. Waiting, running and
  unread sessions are excluded here, so nothing appears twice. A failed session stays in the date sections (or Unread
  until seen) rather than Needs you: it is an outcome, not a blocking wait, and pulling it to the
  top would make every old failure compete with a live question.
- **One bottom action**: a 52 px primary "New session" button inside a 56 px bar with a hairline
  and the safe-area inset. No floating search button; search lives in the nav. The list ends above
  the bar instead of scrolling under a gradient.
- **Search** opens from the nav as a full-width field with Cancel, the familiar iOS pattern. It
  hides the board and searches the server; results reuse the session row with a two-line snippet.
  Cancel restores the previous scroll position.
- **Empty**: a 28 px line glyph, "No sessions yet", one sentence ("Start one from your laptop, or
  tap New session"), and the bottom action. No illustration; there is no art pipeline for this app
  and an invented one would look borrowed.
- **Offline**: a 36 px banner under the title, "Reconnecting…", with a small spinner. The list stays
  readable. When the socket returns, the banner fades; no success toast.

**Why:** the current screen answers "what exists?" The board answers "what needs me?" and keeps the
answer above the fold. The filter sheet disappears because Needs you, Running and Unread are always
at the top; there is no state left to filter for. Removing the duplicate running rows alone shortens the
average list by a third when two sessions are active.

```
 Sessions                              [search] [settings]
 ─────────────────────────────────────────────────────────
 Needs you  2
 ! Fix the off-by-one in paginate()     Allow Bash: npm test
 ! Plan the router split                Approve the plan
 ─────────────────────────────────────────────────────────
 Running now  2
 ◐ Migrate the config loader to TOML                     1:41
   Add a TOML parser path
   Tasks 1 of 4
 ◐ Add cursor pagination to GET /notes                   4:12
   1 job · 2 subagents                               ›
 ─────────────────────────────────────────────────────────
 Unread  1
 ● Draft the 0.4 release notes              notes-api · 1d   ›
 ─────────────────────────────────────────────────────────
 Today
 ○ Bump the lint config to the flat format   web-shell · 3h   ›
 ○ Explain the retry backoff in the queue    queue-worker · 1d  ›
 ─────────────────────────────────────────────────────────
 [                    New session                    ]
```

**Acceptance:** a running or waiting session appears exactly once; Needs you is the first section
when present; there is no filter button or filter sheet; every row is at least 56 px; search opens
and cancels without losing scroll; the screen works at 320, 390 and 430 px wide in all six themes
and both schemes.

### 4.2 Running now: the live row

Keep the name. It is good copy and users know it.

**Row anatomy** (no card, no shadow, a 1 px separator between rows):

1. Status glyph, 17 px semibold title, elapsed at the trailing edge in the live-number role (22 px
   mono, tabular). The elapsed is the current turn, or the oldest live job when there is no turn. Use `4:12` (or `1:04:12`), not `252s`: it is a running clock, not a log line.
   Titles truncate; the clock never does.
2. One line of current work, 13 px secondary: "Add a TOML parser path", "Waiting for approval", the
   running job's label, or "Starting a subagent". Truncate with an ellipsis; never wrap to three lines.
3. A 4 px task progress bar with "2 of 5" only when the session reports todos. Context appears as a
   small chip at the trailing edge only at or above 80% ("Context 82%", amber at 85, red at 95).
   No permanent "ctx" meter and no second bar at rest.
4. A footer, 13 px secondary: "1 job · 2 subagents", with a chevron. Tap expands jobs and subagents
   inline: 44 px rows, mono command or agent name, state word, elapsed. A running job gets a
   trailing Stop that arms on the first tap and fires on the second. This is destructive to work;
   never make it a swipe.
5. Tap the title to open the session; tap the footer to expand. Keep the two hit areas separate.

Show every running session. They are the active work and the reason to open the app; capping the
section would hide the thing the screen exists for. If the list becomes long, the section header
stays and Today scrolls beneath it.

**Why:** Flighty's airport-board rows and Sunlitt's small label over a large time are the right
reference here, not a settings card. The elapsed number is the thing that moves; give it the
trailing edge and tabular figures. Making the live item a row rather than a card keeps one
container language and removes a whole component.

**Acceptance:** one live row per active session; no duplicate in Today or Earlier; the current step
is readable without expanding; jobs, subagents and stop still work; a row with no todos and low
context is visibly shorter; the section is hidden entirely when nothing runs.

### 4.3 Session: prose plus receipts

**Current:** a compact header, then a three-line monospace telemetry bar pinned above the
conversation, a goal line, 14 px prose, one row per tool call, diff cards, a large turn summary
card, and a blinking block for "Working…". The telemetry is the first thing you see in every
conversation, and the tool rows are as loud as the answer.

**Becomes:**

- **Header, 44 px**: back chevron (44), centred 17/22 semibold title. The 13 px secondary subtitle
  is the folder basename and, when dsh reports it, the context percentage (`notes-api · 42%`). It
  turns amber at 80% and says `Context 82%`; below 80 it is quiet. Full path, preset and cost live
  in Session details, the first row of the ellipsis menu. Trailing ellipsis (44). No connection dot.
- **The goal line stays** when a goal is active: a 32 px strip under the header, 13 px sans, a glyph,
  the objective and its status. Tap opens the goal sheet. This is real state, not telemetry, and it
  is the only persistent strip allowed under the header.
- **No telemetry block.** Model, route, tokens, cache figures and cost move to **Session details**
  (section 4.6), one tap from the menu. Context stays in the subtitle because it changes
  what the user should do next; everything else is informational and can wait.
- **Transcript**, 16 px gutter, 12 px between messages, 24 px between turns, max 680 px wide:
  - **User** messages: right aligned, 17/24, `--user` fill, 22 px radius with a 6 px corner at the
    bottom right, 10 by 14 padding, max 82% width. Image attachments as a row of 120 px thumbnails,
    not "🖼 1 image".
  - **Assistant** prose: no bubble, full width, 17/24, 0.75 em paragraph spacing, links in accent
    with no underline. This is the biggest single readability change in the app.
  - **A turn is an answer plus its activity.** The answer is the last assistant text block after the
    last tool call; if the turn ends on a tool call, use the last text block before it and let the
    receipt carry the outcome. Anything before it (narration and tool calls) is activity. A turn
    with no tool calls is just prose.
  - **While running**: the streaming answer stays visible, plus the last three activity rows and a
    quiet "5 earlier steps" disclosure above them. Watching the work is a core use case; do not
    hide the current step.
  - **When the turn ends**: activity collapses into a **receipt row** at the end of the answer.
    Receipt: verdict glyph + "Passed" (13 semibold) + "2 files · 2 commands · 1m 12s" (13
    secondary) + chevron. 44 px minimum, card surface, 14 px radius. Tap expands the files and
    commands. A failed turn is expanded by default with a red leading edge; a passed turn is
    collapsed. The receipt replaces the turn summary card, not the data inside it.
  - **Tool row**, inside the expanded receipt or the live activity: 36 px of ink inside a 44 px hit
    area, 16 px glyph (terminal,
    file, search, globe, list-check), mono 13 px tool name, 13 px secondary summary, trailing 13 px
    mono delta (`+15 −0`). Running row: the working glyph spins; no blinking block. Failed row:
    red glyph and a red word, not just red text.
  - **Diffs**: keep the current folding and the no-line-number rule (dsh does not send numbers).
    File header 13 px mono plus stats, body 13 px mono at 1.5 line height, full-width add/remove
    tints, tap the header to fold. The tint stays soft; the `+`/`−` gutter is the primary cue.
  - **Code blocks**: 13 px mono, sunken surface, 10 px radius, horizontal scroll, a small Copy
    action on the block. No syntax highlighting; see section 7.
  - **Working**: one row at the end of the feed, the working glyph, "Working" in 13 px and elapsed
    in mono tabular. No "▍" blink. The current step is the line above it.
  - **Jump to live**: when the user has scrolled up while a turn runs, a 44 px pill above the
    composer, "New activity", with a down arrow. Tap re-pins to the bottom. It is not a permanent
    floating button.
  - **Load earlier**: a quiet 44 px footer button, not a full-width ghost that competes with the
    composer.
- **Session details** (section 4.6) holds everything the status bar used to show.

```
 ‹   Fix the off-by-one in paginate()        ●   ⋯
     notes-api · 42%
 ────────────────────────────────────────────────────────
                                  ┌──────────────────────┐
                                  │ GET /notes returns   │
                                  │ 21 notes...          │
                                  └──────────────────────┘
 The handler computes end as start + limit + 1.
 The page now holds exactly limit notes, and the last
 page still reports hasMore.
 ✓ Passed · 2 files · 2 commands · 1m 12s               ›
 ────────────────────────────────────────────────────────
 [ + ]  [mic]  Message dsh                          [↑]
```

**Why:** Crouton's lesson is to show the current step, not the whole machine. Tiimo's calm timeline
and Flighty's one-line status both point at the receipt: one row per finished thing, expanded only
when the user asks. The transcript becomes an answer with a work log attached, which is what a
coding session actually is.

**Acceptance:** a completed turn with tools is one receipt plus the answer, not a wall of rows; a
running turn shows the current step and streaming text; a failed turn opens itself; all telemetry
is still available in details; diffs still open and fold; the transcript is readable at the
largest iOS text size and 200% zoom, and in every theme; history replay and live streaming
produce the same grouping.

### 4.4 Composer: one field, one primary action

**Current:** a full-width input, then a row of plus, `Aa`, mic, queue/steer chip, send, stop. It is
functional but reads as a toolbar. The two-state queue/steer chip is the most cryptic control in
the app.

**Becomes:**

- A hairline top, canvas surface, 8 by 12 padding plus safe area. No floating dock, no shadow.
- Attachments above the field as 56 px thumbnails with a 22 px remove glyph inside a 44 px hit area.
- A queued-message banner when messages are waiting: "2 queued · Review", 13 px, one line. Review
  opens the existing queue editor; edit and remove stay.
- **One field**: 44 px minimum, 22 px radius, sunken fill, 17 px text, placeholder "Message dsh",
  grows to five lines then scrolls. Focus ring in accent at 45% opacity, 3 px.
- **Left**: a 32 px plus circle inside a 44 px hit area. It opens a small action sheet: Photo
  library, File, Prompt template, Commands. That is where `Aa` goes, and Commands keeps a
  discoverable path to the same list the slash popover shows. The mic stays visible in the row,
  because dictation is one of the few phone-native advantages this app has and burying it would be
  a regression.
- **Right**: a 32 px send circle inside a 44 px hit area, accent when enabled, muted when empty.
  While a turn runs and the field is empty, the same control morphs into a stop square. One
  control, one position, no second button appearing beside it.
- **Queue vs steer, only when it matters**: while a turn runs and there is text, a 32 px segmented
  "Queue / Steer" inside a 44 px row appears above the field at the trailing edge. It is
  contextual and labelled. Default is Queue. The old always-visible chip is gone, but the feature
  is not.
- **Keyboard**: inputs stay at 16 px or larger to prevent iOS zoom; the composer sits above the
  keyboard via `interactive-widget=resizes-content` with a `visualViewport` fallback; focusing the
  field scrolls the caret into view.
- **Decisions** sit above the composer (section 4.5), capped at 55 vh with their own scroll. The
  composer is never pushed off screen by a long approval.

**Acceptance:** one primary control at a time; `Aa` is gone from the default row but the mic stays
where the Web Speech API exists; queueing is the default while running; steer is reachable and
labelled; attachments and templates still work; the composer stays visible with the keyboard open;
44 px hit areas throughout.

### 4.5 Decisions: approval, question, plan

These are safety surfaces. Polish here means clarity, not elegance.

- **Approval card**: kicker "APPROVAL · Bash" in 11 px tracked caps, amber. Title 17 px semibold:
  "Run this command?" Instead of "Allow Bash?". One line of why at 13 px. The command in a 13 px
  mono block, the full text with no max height; the decision stack itself scrolls, so Allow sits
  after the whole command. No ellipsis, no expand step, no hidden middle. Copy is an action on the
  block. Buttons stacked, 46 px: **Allow** (the only filled control, accent) then **Deny** (plain
  text, 46 px hit area). Waiting time at the trailing edge of the kicker row, 11 px mono small.
  Never truncate the command; a scrolling card is fine, a hidden middle is not.
- **Question card**: kicker "QUESTION", prompt 17 px, options as 44 px rows with a check, optional
  free-text field, **Send answer** primary. Selection is never colour-only; the check is the cue.
- **Plan review**: a compact card in the conversation: kicker "PLAN REVIEW", the goal at 17 px, the
  first two steps at 13 px, **Review plan** primary. It opens a large sheet with the full plan in
  17/24 prose, a 44 px feedback field, and a sticky footer: **Approve** (the only filled
  control), **Keep planning** (sunken fill) and **Reply instead** (plain text). This gives a long
  plan room to be read instead of forcing it into a 36 vh box between the transcript and the keyboard. The card stays behind the sheet, so
  dismissing the sheet loses nothing.
- **Expired**: muted card, "This request expired", and a single action to return to the session.
  No dead buttons.
- **One primary while a decision waits**: Allow, Approve or Send answer is the only filled accent on
  screen. The composer is still available, but its Send is quiet; a typed message queues and does
  not compete with the decision. When the decision clears, Send returns to primary.
- **Notifications name the request, they never approve it.** iOS web push has no action buttons, so
  the notification text carries the tool and command ("Allow Bash: npm test?") and tapping opens
  the session with the decision card waiting. No approval happens from a notification or the list.
- **Never**: auto-approve, swipe to approve, dismiss on scrim tap for an approval that is the only
  thing blocking the turn, or colour as the only difference between Allow and Deny.

**Acceptance:** the command is fully readable before approving; two filled buttons never compete;
a plan can be read at 17 px; every decision has one primary and one escape; expired state is
explicit; the card stack scrolls without moving the composer.

### 4.6 Session details: where the telemetry goes

A grouped sheet opened from the first row of the session menu, not a permanent bar.

- **Route**: model, provider, agent preset, full folder path.
- **Context**: a 4 px bar, percentage, window size, and a sentence when above 80% ("Context is
  nearly full. Start a new session or compact before the next long turn."). Only state what dsh
  reports; do not invent a compact command.
- **Usage**: the existing per-turn table (turn, in, out, cache read, cache write, est.), with the
  note that rows cover the loaded history.
- **Cost**: estimated total, "USD, from the shipped table; override in Settings > Prices", and the
  model prefix used.
- **Session**: folder, preset, started, updated, message count if available.
- **Actions**: Refresh, Copy folder path. No destructive action.

This is a demotion, not a deletion. The numbers are still one tap away, and they are easier to read
in a sheet than in a three-line strip above a conversation.

**Acceptance:** every figure the old status bar showed is present; the context percentage turns
amber at 80% in the header; `statusline` tests are updated to the new location; no session opens
with telemetry above the first message.

### 4.7 Sheets, settings and the menu

**Current:** one generic sheet holds 14 different screens, and the theme and notification entries are
duplicated between the home menu and the session menu. The list is flat, so Archive sits next to
Refresh.

**Becomes:**

- **One sheet shell with a back stack.** Medium detent (around 50 vh) for quick lists, large
  (around 92 vh) for forms and reading. Grabber, a title (17 px centred for quick lists, 22 px
  left for large forms), back chevron when a sub-sheet
  is open, Done or Cancel, a sticky footer for the primary action, drag to dismiss from the top,
  scrim tap, Escape, focus trap, focus returned to the trigger. Sub-sheets push in from the right
  inside the same sheet instead of replacing it with no way back. The redundant X goes; the grabber
  and the title row do the work. A blocking safety decision (approval) never uses a dismissible
  sheet.
- **Grouped settings** use an inset list: card surface, 14 px radius, 52 px rows, separators inset
  to the text, 13 px secondary value, chevron. Rows carry a label and a value, not an explanatory
  subtitle on every line; explanations move to a group footer. Destructive rows are their own group
  at the bottom, in red, with a confirmation that names the consequence.
- **Two destinations, not two menus that overlap**:
  - **Session menu** (from the trailing ellipsis): Session details, Model, Goal, Scheduled prompts,
    Rename, Fork, Export log, then Settings, then Archive in its own group.
  - **Settings** (app-wide, from the gear in the Sessions nav): Notifications, Appearance, Plugins &
    connectors, Prices (under Advanced), This device (QR, open full dsh), About.
- **Removed from both menus**: Commands (the slash popover and the plus menu already list them),
  Refresh (the app refreshes on resume and reconnect, with a manual action in Session details), and
  Open full dsh web UI from the primary list (it moves to About).
- **Appearance**: six theme cards in a two-column grid, each with a split swatch showing the light
  and dark canvas with the theme's accent, and its name. Selected has a ring and a check. All six
  themes stay, with the same ids, labels and `dsh-rc.theme` key. A note says the theme follows the
  device's light or dark setting; there is no separate light/dark toggle. `theme.js` gains swatch
  values (bg, card, accent) and a test keeps them in sync with `style.css`.
- **Notifications**: a native switch where the platform supports one

- **Prices**: keep the JSON editor, in mono, under Advanced, with a sticky Save. It is a developer

- **Scheduled prompts**: list, detail, form; human next-run text; two-tap delete stays.
- **QR**: keep the white tile so it scans in dark mode; add Copy and, where available, Share via
  `navigator.share`. Never show a real tunnel URL in a committed screenshot.
- **About**: version, Open full dsh web UI, source link.

**Acceptance:** one Settings destination; no duplicated theme or notification entries; every old
menu action remains reachable from the screen it belongs to in at most two taps; all six themes
selectable with a preview and surviving reload; Archive is separated and confirmed; sheets trap
focus and return it.

### 4.8 New session

**Current:** a sheet with a raw path input, a folder list, a native `<select>` for the preset, and a
Start button. It works, but the raw path is the most prominent control, which makes a simple task
feel like a shell prompt.

**Becomes:** a large sheet with:

- Title "New session" and Cancel.
- **Recent folders** as 56 px rows: folder glyph, name, 13 px mono tilde path, check on the
  selected one. This is the primary control.
- **Browse folders** as a row; the existing browse flow and breadcrumb stay.
- **Enter a path** behind a disclosure, mono, for the rare case. Validation happens on Start, not
  on every keystroke.
- **Agent preset** as a row with the current value and a chevron, opening a small list. A native row
  is better than a `<select>` on iOS and matches the rest of the sheet.
- **Start session** pinned at the bottom, disabled until a folder is chosen, with a one-line
  summary above it ("Starts in notes-api · Standard").
- Failures appear inline above the button, not as a toast that disappears while the sheet stays
  open.

**Acceptance:** a session can be started with two taps from the sheet; the path is still available;
the preset is discoverable; the keyboard does not cover Start; an error keeps the form state.

### 4.9 States: offline, empty, loading, errors

- **Offline**: a 36 px banner under the title, "Reconnecting…", with a small spinner. It does not
  block reading. On reconnect it fades out. No toast per reconnect.
- **Empty**: one glyph, one sentence, one action. No illustrations, no exclamation marks.
- **Loading**: a centred spinner for the first load; an inline "Loading earlier…" for history; a
  quiet placeholder row for the list only if the first load exceeds around 300 ms. No skeleton
  screens on every card.
- **Errors**: inline where the work is (history error in the feed, create error in the sheet, push
  error in Settings), with a human sentence first and the technical message in 13 px secondary.
  Toasts only for transient confirmations ("Copied", "Archived") and nothing else.
- **403 helper**: keep it; restyle as a card with a Copy action. It is a real setup path, not an
  error to hide.
- **Toast**: one at a time, 13 px, icon, 2.4 s, above the composer, with a 180 ms fade and rise. No
  queue of stale messages.

## 5. The system

### 5.1 Type: two registers

The research's serif-over-sans rule is right for a warm consumer journal. It is wrong here.
Importing a book serif would make dsh-rc look like a different product, add a font file and a
licence obligation, and fight the mono culture of a coding tool. New
York (`ui-serif`) would be native and free, but a serif over a transcript of shell commands reads
as costume.

The equivalent move for an instrument is a **two-register system**:

- **SF Pro / system sans** for anything human: titles, labels, buttons, prose.
- **SF Mono / system mono** for anything machine: commands, paths, model ids, token figures,
  elapsed times, code, diffs.

No serif. No downloaded font. This is also the only choice that satisfies the repo's no-CDN and
vendor-licence rules without adding weight.

| Role | Family | Size / line | Weight | Tracking | Used for |
|---|---|---|---|---|---|
| Display | SF Pro Display | 34 / 41 | 700 | -0.02 em | "Sessions" large title |
| Title | SF Pro | 22 / 28 | 600 | -0.01 em | Large form pages, reading screens |
| Section | SF Pro | 13 / 18 | 600 | 0 | Section headers, list group labels |
| Nav title | SF Pro | 17 / 22 | 600 | -0.01 em | Compact header, session title |
| Body | SF Pro | 17 / 24 | 400 | 0 | Chat prose, form text |
| Callout | SF Pro | 15 / 20 | 400 | 0 | Card descriptions, secondary prose |
| Caption | SF Pro | 13 / 18 | 400 | 0 | Metadata, helper text |
| Kicker | SF Pro | 11 / 13 | 600 | +0.08 em, uppercase | Decision kickers, small status labels |
| Button | SF Pro | 17 / 22 | 600 | 0 | Primary and secondary buttons |
| Mono | SF Mono | 13 / 18 | 400 | 0 | Commands, paths, code |
| Mono small | SF Mono | 11 / 14 | 400 | +0.04 em | Model ids, token labels |
| Mono number | SF Mono | 13 / 16 | 500 | 0, tabular | Deltas, figures in tables |
| Live number | SF Mono | 22 / 26 | 500 | 0, tabular | Elapsed on a live row |
| Receipt | SF Pro | 13 / 18 | 600 verdict, 400 meta | 0 | Turn receipt |

Sizes are px at the default iOS body size (17 px = 1rem). Implement them in rem so
`-apple-system-body` scales them; see the Dynamic Type rule below. At larger text sizes only the
display title is clamped, and it may wrap; bars grow with their content, and body, labels and
controls are never clamped.

Rules:

- **No body text below 15 px.** No label below 13 px except the 11 px kicker and mono-small.
  Replace every 12 px and 10.5 px declaration.
- **Three UI weights**: 400, 600, 700. Delete 550 and 650. Mono figures may use 500; that is the
  only fourth, and only for numbers.
- **Tabular figures** (`font-variant-numeric: tabular-nums`) on every number that ticks or aligns:
  elapsed, tokens, cost, deltas, percentages. This is what stops a live clock from jittering.
- **Sentence case** everywhere except kickers. No all-caps mono labels such as "BACKGROUND JOBS";
  use a 13 px semibold label with a count.
- **Numbers carry their unit** in prose ("1m 12s", "2 of 5", "$0.0026"). In tables, the column
  header carries the unit. The live elapsed is the one exception: a running clock reads `4:12`,
  because it is a timer, not a log line.
- **Dynamic Type, for real.** On iOS and iPadOS, `html { font: -apple-system-body; }` makes the root
  size follow the user's Text Size setting, and all rem sizes scale with it. This is a WebKit system
  font keyword that has existed since Safari 7; it is not available on other platforms, where the
  declaration is ignored and `font-size: 100%` remains. Use it, then override `font-family` with
  the system sans stack so the app keeps its own face. Size everything in rem.
  ([furbo.org on Dynamic Type on the web](https://furbo.org/2024/07/04/dynamic-type-on-the-web/))
- **Clamp only the display title.** At the largest accessibility sizes a 34 px title can dominate
  the screen; cap that one role with `min()` and let it wrap. Do not clamp labels, controls, or
  prose, and do not fix the height of a bar: use `min-height` and let it grow. Test at the largest
  iOS text size, not only at 200% browser zoom.
- **Line length** capped at 68 characters (around 680 px) in prose. On a phone the gutter does the
  work; on a wide browser the column is centred.
- **Truncation** is for titles and one-line summaries, never for commands, approval details, or
  code the user must judge.

### 5.2 Colour: a semantic layer, not a new palette

The six themes stay exactly as user choices. The redesign introduces a semantic layer that aliases
the existing primitives, so a theme only has to be edited in one place and no palette is replaced.

```
--canvas        -> var(--bg)          page
--surface       -> var(--card)        cards, list rows, sheets
--surface-sunk  -> var(--bg2)         fields, code, tracks
--surface-fill  -> var(--bg2)         secondary buttons, pressed rows
--text          -> var(--fg)
--text-2        -> var(--muted)
--separator     -> var(--line)
--tint          -> var(--accent)
--on-tint       -> var(--accent-fg)
--success       -> var(--ok)
--warning       -> var(--warn)
--danger        -> var(--err)
--card-border   -> transparent        var(--line) in the contrast theme
--focus         -> color-mix(in srgb, var(--accent) 45%, transparent)
--scrim         -> rgb(0 0 0 / .42)
--shadow-sheet  -> 0 -12px 48px rgb(0 0 0 / .28)
--shadow-float  -> 0 2px 12px rgb(0 0 0 / .18)
```

Why aliases rather than a new palette:

- Every theme already passes `test/theme-contrast.test.mjs` for its primitive pairs. Aliases
  resolve per theme with no new values, so those tests keep meaning what they meant. That covers
  the primitives only. When a component puts text on a new surface or tint, add that exact pair to
  `textPairs` in the same PR; an alias is not coverage.
- The contrast theme needs visible borders and no reliance on shadow. It gets `--card-border:
  var(--line)` and a flat sheet edge. The colourblind theme's shape cues are folded into the
  universal glyph set (section 5.4), so shape no longer depends on which theme is active.
- Seasonal themes keep their character because their `bg`, `card`, `accent`, `ok`, `err` and `warn`
  are untouched. The redesign changes what is painted with them, not the paint.

Rules:

- **Accent is scarce**: one filled accent control per screen (the primary action), plus links,
  selection, focus ring and the live glyph. Do not make every border, icon and progress bar accent.
- **Status colours are semantic**: green for passed/connected, amber for waiting/warning, red for
  failed/destructive. A status never appears without a glyph or a word. This is already true in the
  colourblind and contrast themes; make it true everywhere.
- **Two text tones** only: `--text` and `--text-2`. Do not add a third grey for "quiet" text; it
  will fail contrast somewhere. Quiet comes from size and weight, not lightness.
- **Tints** are `color-mix` of the status colour at 10 to 14% over the surface. Text on a tint is
  `--text` or the status colour, whichever the existing test pairs cover. Add every new pair to
  `textPairs` in the contrast test before shipping. The test exempts the default theme from a few
  pairs; do not lean on that. A component that only passes because of an exemption is not done.
- **No gradients.** No decorative shadows on cards. One sheet shadow, one floating-button shadow.
- **Material** (optional, one place): the nav bar, bottom bar and sheet header may use a 92% opaque
  canvas plus `backdrop-filter: blur(20px) saturate(180%)`, with a solid fallback. At 92% the
  contrast pairs are effectively unchanged. Do not put blur on scrolling cards; it costs frames
  and adds nothing.
- **High contrast**: borders stay, shadows go, focus ring is 2 px solid accent, and every separator
  is `--line` (already 3:1).
- **Dark and light** are both first-class. The current screenshots are dark only; the redesign must
  ship light screenshots in the PR evidence and spot-check every theme in both schemes.

### 5.3 Spacing, layout, radius, elevation

**Spacing** is a 4 pt grid. The only allowed values:

| Token | px | Use |
|---|---|---|
| `--s-1` | 4 | Icon to text, tight pairs |
| `--s-2` | 8 | Stack inside a card, button gap |
| `--s-3` | 12 | Row padding, list gap |
| `--s-4` | 16 | Screen gutter, card padding |
| `--s-5` | 20 | Sheet gutter, roomy card |
| `--s-6` | 24 | Section gap |
| `--s-8` | 32 | Group gap, large title to content |
| `--s-10` | 40 | Empty-state breathing |
| `--s-12` | 48 | Rare; hero spacing |

- Screen gutter **16**. Card padding **16**. List row height **56** (12 vertical). Nav bar **44**
  plus safe area. Bottom bar **56** plus safe area. Sheet padding **16** with a **20** top.
- Section gap **24**, group gap **32**. Do not use 10, 11, 14, 18 or 22 for spacing except the
  bubble radius and the safe-area math.
- Content max width **680**, centred. On a wide browser the app is a phone column, not a stretched
  dashboard. A true tablet layout is deferred (section 7).

**Radius** has five values:

| Token | px | Use |
|---|---|---|
| `--r-sm` | 10 | Fields, small buttons, code blocks |
| `--r-md` | 14 | Cards, list groups, receipts |
| `--r-lg` | 20 | Sheet top corners |
| `--r-bubble` | 22 | User message bubbles, composer field |
| `--r-pill` | 999 | Pills, segmented track, status chips |

Delete 5, 6, 8, 12, 18, 20-on-cards and the asymmetric card radii. The bubble's 6 px corner is the
only intentional asymmetry.

**Elevation**:

- Cards: none. Surface contrast and a separator do the work.
- Sheet: one soft upward shadow, or a 1 px top hairline in the contrast theme.
- Floating jump-to-live: a small shadow, because it sits over content.
- Nothing else. If a surface needs a shadow to be understood, it needs a better layout instead.

**Hairlines**: 1 px, `--separator`, used between rows and under bars. Inset separators start at the
text edge, not the screen edge. The nav and bottom bar separators appear only when content is
scrolled beneath them, with a 120 ms fade.

### 5.4 Components

| Component | Anatomy | Rules |
|---|---|---|
| **Nav bar** | 44 px, optional large title, leading/trailing slots | One trailing action preferred; two maximum; no grey circles |
| **List row** | 56 px, leading glyph, title 17, meta 13, trailing chevron | Pressed fill; no hover; separator inset 16 |
| **Card** | Surface, 14 radius, 16 padding, optional kicker | No shadow; border only in contrast; one idea per card |
| **Button** | Primary filled accent; secondary quiet fill; tertiary plain accent; destructive red | 46 px, 17 semibold, 10 radius; never two filled accent buttons in one row |
| **Icon button** | 44 by 44, 24 glyph, no background | Pressed fill; 32 px circle only inside the composer |
| **Field** | 44+, sunken fill, 10 radius, 17 text | Focus ring accent 45%; no 16 px trap; label above, not placeholder-only |
| **Segmented** | 32 px track, 28 px thumb, 44 px row | Sliding thumb 220 ms; used for Queue/Steer; the home board uses sections, not a filter |
| **Banner** | Icon, 13 text, optional action, 36 to 44 px | Inline, not a toast, for persistent conditions |
| **Sheet** | Grabber, title, back/Done, body, optional footer | Medium/large, back stack, drag, scrim, Escape, focus trap; X removed |
| **Status glyph** | 16 px, one shape per state | The same shape in every theme and on every surface (see below) |
| **Receipt** | Verdict, meta, chevron, 44 px | Collapsed for pass, open for fail; expands to tool rows |
| **Tool row** | 16 glyph, mono name, summary, delta | 36 px; status by glyph + word; no coloured bullet alone |
| **Code block** | Mono 13, sunken, 10 radius, Copy | Horizontal scroll; no syntax colours |
| **Diff** | File header, stats, add/del lines, folds | No fake line numbers; `+`/`−` gutter is the cue |
| **Empty state** | 28 glyph, 17 title, 15 body, action | One sentence, no art |
| **Toast** | Icon, 13 text, pill | One at a time, 2.4 s, above composer |

**One status vocabulary.** Today the list, tools, jobs and subagents each draw state differently,
and the shape cues exist only in the colourblind and contrast themes. Replace all of it with one
16 px glyph set used everywhere and in every theme:

| State | Glyph |
|---|---|
| Idle | Hollow ring |
| Working | Spinning arc |
| Needs approval | Amber disc with `!` |
| Question | Amber disc with `?` |
| Unread | Filled accent dot |
| Done | Tick |
| Failed | Cross |
| Stopping | Amber triangle |
| Stopped | Neutral square |

This is stronger than theme-scoped cues: shape is never a special case, and a person using the
default theme gets the same redundancy as a person using the colourblind theme. Keep approval and
question distinct: a single amber dot would erase the difference between "allow this command" and
"answer this question." Stopping (a turn is being cancelled) is a triangle; stopped (it ended that
way) is a square, so the two never read as the same state. The tick and cross are for tools and
receipts; an idle session stays a hollow ring, because "done" and "idle" are not the same thing.

It also lets the theme-specific shape-cue block in `style.css` go. Because
`theme-contrast.test.mjs` currently asserts those selectors exist, the same PR must replace that
assertion with one that checks the universal glyph classes are present and distinct, including
approval versus question and stopping versus stopped. Do not remove the shape requirement from the
test; move it.

Component rules that matter more than the table:

- **One primary action per screen.** On Sessions it is New session. In a session it is Send, or
  Allow when an approval blocks the turn. In a sheet it is the footer action. Everything else is
  secondary or tertiary.
- **Button hierarchy is visible without colour**: filled, filled-quiet, plain. A person who cannot
  distinguish the accent still sees the primary.
- **Every icon-only control has an accessible name.** Every destructive action names its
  consequence.
- **Rows are not cards inside cards.** If a list is a group, it is one card with inset separators,
  not eight cards with gaps.
- **Visible size is not hit size.** A 32 px circle, a 28 px segmented thumb, or a 36 px tool row
  sits inside a 44 px tappable box (padding or a pseudo-element). Audit the hit box, not the ink.
- **No nested scrolling** unless the inner region is a code block, a diff, or a capped decision
  stack. Nested vertical scroll on a phone is a trap.

### 5.5 Motion

Motion is small, purposeful and interruptible. It exists to show where a thing came from and where
it went.

| Token | Value | Use |
|---|---|---|
| `--dur-fast` | 120 ms | Press, focus, scroll hairline |
| `--dur-base` | 220 ms | Disclosure, segmented thumb, scrim, toast |
| `--dur-slow` | 320 ms | Sheet in, view push |
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | Most changes |
| `--ease-emphasized` | `cubic-bezier(0.32, 0.72, 0, 1)` | Sheets, push, segmented |
| `--ease-exit` | `cubic-bezier(0.4, 0, 1, 1)` | Dismissals |

Interaction by interaction:

- **Press**: rows get a fill highlight instantly, no transition. Icon buttons fade to 0.72 over
  100 ms. Round composer buttons scale to 0.94 over 120 ms. No universal "scale every button"; it
  reads as a web toy.
- **Sheet**: translateY from 100% to 0 over 320 ms with the emphasized curve, scrim fades over
  220 ms. Dragging follows the finger 1:1, with resistance past 120 px. Dismiss at 30% or on
  velocity, 220 ms out. The sheet can be grabbed while it is still animating in.
- **View push**: Sessions to Session slides in from the right over 300 ms; the outgoing view moves
  to -24% and dims slightly. Back reverses over 260 ms. Use transform and opacity only. If the
  history direction is unknown, crossfade over 150 ms instead.
- **Segmented**: the thumb moves over 220 ms; the label colour crossfades.
- **Disclosure** (receipt, jobs, plan card): 220 ms on `grid-template-rows` from 0fr to 1fr, plus a
  chevron rotate. If that is janky on an old phone, use `<details>` with no height animation; the
  correct fallback is instant, not a stutter.
- **Toast**: 8 px rise and fade in over 180 ms, out over 160 ms.
- **Progress**: width changes over 240 ms; the number itself does not animate.
- **Working glyph**: a 0.9 s linear rotation while a turn or job is live. It is the only looping
  animation; no pulsing dots, no scale, no glow.
- **Scroll edge**: hairline opacity over 120 ms.
- **No animation** on: list load stagger, card shadows, font sizes, layout height except
  disclosures, scroll position except an explicit jump (which is instant), or every element on
  route change.
- **Reduce Motion**: every transform becomes none; fades stay at 120 ms; the spinner slows to 3 s;
  auto-scroll becomes instant. This is a real setting on iOS, not an edge case.

### 5.6 Native details

- **Targets**: 44 by 44 pt minimum, 8 pt between adjacent targets. Inline text links in prose are
  exempt. Audit with a script in the screenshot harness.
- **Safe areas**: top and bottom via `env(safe-area-inset-*)`. The bottom bar, composer and sheet
  footer all account for the home indicator. The jump-to-live button sits above the composer, not
  at a hard-coded 130 px.
- **Keyboard**: 16 px minimum on inputs, `interactive-widget=resizes-content`, a
  `visualViewport` fallback, and scroll-into-view on focus. Test with the keyboard open on a real
  iPhone, not only a desktop emulator.
- **Scroll**: momentum scrolling, `overscroll-behavior: contain`, no custom pull-to-refresh. The
  app refreshes on `visibilitychange` and reconnect; Session details has a manual Refresh.
- **Back**: keep the `#s/<id>` route and `history.pushState`. The browser back gesture is the
  native gesture; do not implement a competing edge swipe.
- **Focus**: `:focus-visible` only, 2 px solid accent with a 2 px offset for keyboard focus. Fields
  may use the soft 3 px ring while typing. Do not remove the outline without a replacement. Sheets
  trap focus and restore it.
- **Hover**: wrap hover styles in `@media (hover: hover)`. Touch devices must never keep a sticky
  hover state.
- **Selection**: allow text selection in the transcript, code and diffs. Disable it only on
  controls and rows.
- **PWA**: keep standalone display, `viewport-fit=cover`, the per-theme `theme-color` meta and the
  pre-paint `theme.js`. Check the status bar in light themes on a device; `black-translucent` is
  right for dark and questionable for light. Choose one behaviour and document it.
- **Dynamic Type**: `html { font: -apple-system-body; }` plus rem sizing gives the user's iOS text
  size on iPhone and iPad. Clamp only the display title and let it wrap; bars use `min-height` and
  grow with their content. Never clamp body, labels, or controls. On non-Apple platforms the
  declaration is ignored and the 100% fallback applies.
- **Badge, follow-up**: where installed to the Home Screen and notifications are allowed,
  `navigator.setAppBadge` the needs-you count and `clearAppBadge` at zero. Feature-detect; never
  block the UI on it. It is unavailable in a normal Safari tab by design. Keep it out of the first
  release ([WebKit Badging API](https://webkit.org/blog/14112/badging-for-home-screen-web-apps/)).
- **Native switch**: prefer `<input type="checkbox" switch>` for on/off settings in Safari 17.4+;
  fall back to a styled 44 by 28 switch inside a 44-high row. Do not use the hidden-switch trick to
  fake haptics on Allow or Deny.
- **Icons**: a hand-drawn inline set on a 24 px grid, 1.75 px stroke, round caps: search, settings,
  plus, arrow up, stop, chevron left/right/down, close, check, alert triangle, alert circle, info,
  folder, file, terminal, globe, list-check, clock, archive, fork, download, bell, palette, plug,
  QR, mic, camera, doc. No SF Symbols (licence), no icon font, no CDN.
- **Performance**: animate transform and opacity only; passive scroll listeners; no layout reads in
  scroll handlers; no backdrop blur on scrolling content; the clock updates text, not layout.
- **Accessibility**: labels on every icon, `role="dialog"` and `aria-modal` on sheets, a focus trap
  and restore, `aria-live` for turn end and new approvals (not every token), reduced motion, the
  largest iOS text size, no colour-only status. Run VoiceOver on the home board and one approval.

per-turn token table, queue editing, dictation, the 403 helper, the diff folding, or the six themes.

## 7. What not to do

- **No bottom tab bar.** The app has two destinations, Sessions and a Session. A tab bar would
  invent a third (Settings? Running?) and flatten a clear hierarchy. The research's three tabs
  belong to an app with three real places. Native is not a tab bar; native is the right structure
  for the content.
- **No serif, EB Garamond, or downloaded font.** It is another product's voice, it adds a licence
  and a payload, and it fights the mono register. Use SF Pro and SF Mono. If one warm note is ever
  wanted, use `ui-serif` for an empty-state title only, never for the interface.
- **No haptics on arbitrary controls.** iOS Safari exposes no general haptic API.
  `navigator.vibrate` is Android-only and inconsistent. A native `<input switch>` may give one on
  iOS 18, which is a bonus, not a design tool. The Not Boring Habits press feedback does not
  transfer to this platform; good press states do. Do not write "haptic" into the UI copy.
- **No Live Activities or widgets.** Native-only. Push notifications are the available substitute,
  and they already exist.
- **No SF Symbols, icon font, or CDN.** License and repo rules. Draw the 20 glyphs inline.
- **No glassmorphism on cards.** One material on bars at most. Blur everywhere is expensive and
  dates quickly.
- **No skeleton screens on every surface.** One spinner and a quiet list placeholder are enough.
- **No onboarding carousel.** The app has one job and a good empty state.
- **No swipe-to-archive.** dsh has no unarchive; a swipe is too easy for an irreversible action.
  Archive stays in the session menu, separated and confirmed.
- **No fake pull-to-refresh.** It fights the browser scroll and the app already reconnects. Refresh
  on resume and expose a manual action.
- **No iPad side rail in this pass.** `supportsTablet` is still false in the product; a rail is a
  product decision, not a CSS one. Centre the column at 680 px for now. Revisit if dsh-rc claims
  iPad.
- **No syntax highlighting.** It needs a parser or a dependency and a colour system per theme. The
  diff colours are the only code colour that earns its keep.
- **No new build step or framework.** No React, Tailwind, CSS-in-JS, icon package, or animation
  library. The repo's no-build property is part of the product.
- **No light/dark toggle.** Themes follow the device by design. Appearance picks the theme; the
  scheme stays automatic.
- **No confetti, celebration, or sound.** An approval is a safety gate, not a win.
- **No invented data.** If dsh does not report context, tokens or a cost, show nothing or "n/a";
  never a zero that looks like a reading.

## 8. Build order: eight focused PRs

Principles:

- Foundations first. No screen work before the tokens exist.
- One structural change per PR. Do not mix a token refactor with a layout rewrite.
- Every PR updates its tests and its screenshots in the same diff, passes `npm test`, and runs
  `scripts/leak-check.sh` before pushing.
- Every PR is independently revertable. After PR 3, 5 and 7 the app is in a shippable state.
- Branch, PR, never push to `main`. Conventional Commits, scope `ui`, GitHub no-reply author.
  Read the diff for private data before merging. Screenshots come from `scripts/demo-dsh.mjs` only,
  never a real instance.

## 9. Definition of done

A screen is done when all of these are true:

- One primary action, visually and structurally.
- No body text below 15 px; no label below 13 px except the 11 px kicker.
- Every interactive hit box at least 44 by 44, with 8 px between adjacent targets; compact ink
  may be smaller.
- No status conveyed by colour alone; glyph and word are present.
- No permanent telemetry; context appears only when it changes a decision.
- All six themes and both schemes render, with the contrast and colourblind themes checked first.
- Light and dark screenshots exist in the PR.
- It works at 320, 390 and 430 px, with the keyboard open, at the largest iOS text size and 200%
  browser zoom, and under Reduce Motion.
- VoiceOver can name every control and read the transcript in order.
- No layout shift when a clock ticks or a progress bar updates.
- `npm test`, `scripts/leak-check.sh`, and a regenerated screenshot set pass.

## 10. Decisions and open questions

### Decided

- **No serif.** Two registers, SF Pro and SF Mono, for the reasons in section 5.1.
- **No tab bar.** Two destinations are a hierarchy, not a tab set.
- **Sections are the filter.** Needs you, Running now, Unread, Today, Earlier. The filter sheet and
  button are removed, not replaced; every old filter view has a section.
- **Telemetry moves, it does not disappear.** Session details, with the context percentage kept in
  the header subtitle because it changes what to do next.
- **One status vocabulary.** The same 16 px glyphs on sessions, tools, jobs and subagents, in every
  theme; the theme-scoped shape cues are retired.
- **The mic stays visible.** Templates move into the plus menu; dictation does not.
- **Dynamic Type is used where the platform provides it.** `font: -apple-system-body` on iOS, rem
  everywhere, only the display title clamped, bars grow.
- **Completed turns collapse; live turns stay visible.** Failure opens itself.
- **Search moves to the nav; New session is the only bottom action.**
- **No swipe-to-archive, no fake pull-to-refresh, no arbitrary haptics, no Live Activities, no iPad
  rail.**
- **The six themes and the `dsh-rc.theme` key are untouched.** The system is palette-agnostic.

### Open, for the owner

1. **Keep activity expanded?** The default is collapsed for completed turns. If watching the full
   log is more important than a short transcript, add a per-device "Keep activity expanded" switch
   in Settings rather than making every session long by default.
2. **Is the desktop/tablet a real target?** The plan centres a 680 px column. A true two-column
   board or side rail is a product decision and should wait until dsh-rc claims iPad or desktop.
3. **The app icon and splash.** Out of scope here. If they are in scope later, they need an
   original mark, not a screenshot of a real instance.
4. **Queue-only or Queue/Steer?** The plan keeps both, contextual. If steer is rarely used, the
   segmented can become a one-line "Queue" hint and the feature can move into the queued message
   row.

### Hard trade-offs

- **Density vs readable type.** Moving body to 17 px makes the transcript longer. The answer is to
  collapse completed activity, not to shrink the type. Review happens in receipts and diffs, which
  keep their density.
- **Watching the work vs calm.** Removing every tool row would be calm and wrong. Keep the current
  step and the last three rows live; collapse only what is finished.
- **Developer data vs a clean header.** The telemetry is useful to the owner and meaningless at a
  glance. Moving it one tap away serves both, but it is a real change in habit. The first week will
  feel like a loss; the details sheet has to be fast and complete.
- **Native fidelity vs the web platform.** The app cannot have haptics on arbitrary controls,
  widgets, Live Activities, or a native tab bar. It can have Dynamic Type, the native switch, safe areas, sheets,
  back and motion, with the app badge as a follow-up. Use those; do not pretend about the rest.
